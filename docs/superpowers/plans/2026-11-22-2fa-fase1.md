# 2FA Fase 1 (mundo da escola) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Permitir que qualquer utilizador da escola active 2FA (TOTP) opcionalmente, com desafio no login web e API, e reposição pelo administrador.

**Architecture:** Reaproveitar as rotas do Fortify já registadas (`user/two-factor-authentication`, `user/confirmed-two-factor-authentication`, `user/two-factor-qr-code`, `user/two-factor-recovery-codes`, `DELETE user/two-factor-authentication`, `POST two-factor-challenge`) com `views => false`: a UI é Inertia/Vue nossa. O login próprio (`AutenticacaoController::store`) deixa de iniciar sessão quando o utilizador tem 2FA confirmado: guarda `login.id`/`login.remember` na sessão e redirecciona para `GET /two-factor-challenge` (nossa página), que submete para o `POST two-factor-challenge` do Fortify. A API devolve um `desafio` de curta duração e ganha um segundo endpoint.

**Tech Stack:** Laravel 12, Fortify 1.36 (`TwoFactorAuthenticatable`), Sanctum, Inertia + Vue, módulos nwidart (`Modules/Autenticacao`, `Modules/Usuario`).

**Spec:** `docs/superpowers/specs/2026-11-22-2fa-fase1-design.md`

## Global Constraints

- **Nunca obrigatório:** nenhum middleware, 403 ou redirecção força a activação do 2FA. Quem não activou entra exactamente como hoje.
- Só TOTP + códigos de recuperação: sem email, SMS ou push (offline).
- Controllers finos: leitura em Service, escrita em Action (`LogService` + `comLog`, como `RedefinirSenhaUsuarioAction`).
- `use` no topo, nunca FQN inline. Uma tabela por migração (esta fase não cria tabelas: colunas já existem em `users`).
- Português nas mensagens ao utilizador. Botões "Cancelar" sempre `btn-light-danger`. Reaproveitar o padrão visual das Definições.
- Sem commit: só `git add` (o commit é do dono).
- Testar o fluxo real: HTTP com os payloads que o Vue envia, e compilar o Vue (`npm run build`).
- Nunca escrever na BD por tinker/SQL em dados reais.

## Review Focus

1. Utilizador com 2FA: após a senha correcta o pedido NÃO fica autenticado (`assertGuest`) e não existe `SessaoDeUtilizador` até o desafio passar.
2. Código errado repetido no desafio (web e API) é limitado (429) em vez de permitir adivinhar 6 dígitos.
3. Código de recuperação só funciona uma vez.
4. Conta desactivada (`estado != 1`) entre a senha e o código não consegue concluir o login.
5. `desafio` da API expira, é de uso único e não serve noutro tenant.
